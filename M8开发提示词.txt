CREATE TABLE `intent` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `from_user_id` BIGINT NOT NULL COMMENT '发起方用户ID（个人或企业）',

  PRIMARY KEY (`id`),
  KEY `idx_from_user` (`from_user_id`),
  KEY `idx_to_user` (`to_user_id`),
  KEY `idx_status` (`status`)

List<Intent> getReceivedIntents(Long userId)：获取当前用户收到的意向列表

Intent getById(Long id)：根据ID查询意向

boolean hasActiveIntent(Long fromUserId, Long toUserId, Long resumeId, Long jobId)：检查是否已有待回应的意向（防止重复发送）

生成 IntentController.java（放在 com.match.controller 包）：
提供以下接口：

POST /api/intent/send：

接收参数：toUserId（接收方用户ID）、resumeId（可选）、jobId（可选）、message（附言）

从 HttpSession 获取当前 userId 作为发起方

自动判断类型：如果当前用户是个人（role=0），type=0（意向书）；如果当前用户是企业（role=1），type=1（邀约）

校验是否已有待回应的意向，如有则返回 Result.error("已发送过意向，请等待对方回应")

设置过期时间为 7 天后

调用 IntentService.sendIntent() 创建记录

返回 Result.success("意向发送成功")

POST /api/intent/accept/{intentId}：

接收方接受意向，状态改为 1（已接受）

返回 Result.success("已接受意向，联系方式已解锁")

POST /api/intent/reject/{intentId}：

接收方拒绝意向，状态改为 2（已拒绝）

返回 Result.success("已拒绝")

GET /api/intent/my-sent：

获取当前用户发出的意向列表（含关联的简历/职位信息和对方用户信息）

返回 Result.success(List<IntentVO>)

GET /api/intent/my-received：

获取当前用户收到的意向列表（含关联信息）

返回 Result.success(List<IntentVO>)

GET /api/intent/contact/{intentId}：

核心功能：联系方式解锁

校验当前用户是否为该意向的参与方（发起方或接收方）

校验意向状态是否为 1（已接受）

如果通过，返回对方的 phone 和 email（需在 User 表中增加 email 字段，若已存在则直接使用）

如果未通过，返回 Result.error("意向未达成，无法查看联系方式")

更新 UserService 和 UserMapper 无需额外修改，MyBatis-Plus 自动映射

## ⚠️ 注意事项

1. **意向防重复**：在 `sendIntent` 方法中，务必检查是否已有相同（fromUserId, toUserId, resumeId/jobId）且状态为 0（待回应）的记录，防止骚扰。
2. **权限校验**：所有意向操作接口都必须校验当前登录用户是否为该意向的参与方，防止越权。
3. **联系方式脱敏**：在意向状态为"待回应"时，前端应显示"对方联系方式将在意向达成后解锁"，而不是直接显示。
4. **过期处理**：建议增加定时任务或查询时过滤 `expire_time < NOW()` 的意向，将其状态自动置为 3（已过期）。
5. **Git 提交**：M8 跑通后立即执行 `git add . && git commit -m "M8 双向推荐与意向沟通完成"`。
