--- 后端开发要求（Java） ---

1. 生成 AdminController.java（放在 com.match.controller 包）：
   提供以下管理接口（所有接口均需校验当前用户是否为管理员）：
   - GET /api/admin/users：
     - 查询所有用户列表（含分页），返回 User 信息（脱敏，不返回 password）
     - 支持按用户名、角色、注册时间筛选

   - GET /api/admin/users/{userId}：
     - 查询指定用户的详细信息（含其简历/职位数据）

   - PUT /api/admin/users/{userId}/status：
     - 启用/禁用用户账号（在 user 表新增 status 字段，0=正常，1=禁用）
     - 接收参数：status（0或1）

   - DELETE /api/admin/users/{userId}：
     - 删除用户（软删除，在 user 表新增 deleted 字段，0=未删除，1=已删除）

   - GET /api/admin/statistics：
     - 获取平台运营统计概览：
       - 用户总数（个人/企业分别统计）
       - 简历总数
       - 职位总数
       - 意向总数（按状态分组：待回应/已接受/已拒绝）
       - 今日新增用户数
       - 今日上传文件数
       - 大模型调用次数（可在 ParseServiceImpl 中计数）

   - GET /api/admin/parse-logs：
     - 获取文档解析日志列表（含分页）
     - 包含：文件名、解析时间、解析状态（成功/失败）、错误信息（如有）

   - GET /api/admin/activities：
     - 获取最近操作日志（如登录、上传、解析、匹配等）
     - 用于监控面板的实时动态展示

2. 增强 User.java 实体类：
   - 新增 status 字段（Integer，默认 0）
   - 新增 deleted 字段（Integer，默认 0）

3. 新增 AdminAuthInterceptor.java（放在 com.match.interceptor 包）：
   - 实现 HandlerInterceptor，在 AdminController 的所有接口前进行拦截
   - 从 Session 获取当前用户，校验 role 是否为 2（管理员）
   - 如果不是管理员，返回 Result.error("无权限访问")

4. 在 WebConfig.java 中注册 AdminAuthInterceptor：
   - 添加拦截器，拦截路径为 /api/admin/**

5. 生成 ParseLogService.java 及其实现类：
   - 记录每次文档解析的日志（文件名、解析时间、状态、错误信息）
   - 存储在数据库 parse_log 表中（需新建表）

6. 新增 parse_log 表（SQL 建表语句）：
   CREATE TABLE parse_log (
     id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
     file_name VARCHAR(200) NOT NULL COMMENT '文件名',
     file_type VARCHAR(20) NOT NULL COMMENT '文件类型（resume/job）',
     user_id BIGINT NOT NULL COMMENT '操作人ID',
     user_name VARCHAR(50) COMMENT '操作人姓名',
     status TINYINT NOT NULL DEFAULT 0 COMMENT '状态：0=成功，1=失败',
     error_msg VARCHAR(500) DEFAULT NULL COMMENT '错误信息',
     parse_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '解析时间',
     PRIMARY KEY (id),
     KEY idx_user_id (user_id),
     KEY idx_status (status)
   ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='解析日志表';
